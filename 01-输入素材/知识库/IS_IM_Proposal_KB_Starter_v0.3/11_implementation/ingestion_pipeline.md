# 知识材料入库流水线

## A. 书籍/课程/官方指南

1. 在 `source_registry.yaml` 登记元数据、官方链接、访问方式与用途；
2. 对未授权商业材料不复制全文；对创建者合法提供的私人研究副本，可在私有知识库中保留全文并记录授权范围；
3. 生成章节文件、页码/行号可追溯切块、本地检索索引，并为高频主题建立理论卡/方法卡/写作卡；
4. 卡片必须带 source ID、章节/页码、审核状态；
5. 只有 `reviewed/approved` 卡片进入生产检索。

## B. 论文

1. 保存元数据并验证期刊等级；
2. 获取合法全文或摘要；
3. 根据证据等级抽取论文卡；
4. 每个关键判断记录页码/章节；
5. 连接 theory IDs、method IDs、topic tags；
6. 生成或更新 evidence claims；
7. 不自动把单篇论文的“未来研究”当作真实研究空白。

## C. 新研究范式

1. 触发 `KB_PARADIGM_MISSING`；
2. 搜索官方方法标准、权威教材和原始方法论文；
3. 至少两类来源交叉验证；
4. 建立范式文件和最低来源列表；
5. 人工审核后从 `draft` 升级为 `seeded/reviewed`。

## D. 质量抽检

每批入库随机抽检：

- 期刊等级是否匹配版本；
- DOI/题名/作者是否一致；
- 摘要结论是否被过度扩写；
- 引用页码是否正确；
- 理论和方法标签是否可解释；
- 是否遗漏相反证据。


## E. 本地全文入库（创建者提供）

1. 原文文件只读保留，并计算SHA-256；
2. 以目录页的PDF页码锚点拆分章节；
3. 每个chunk记录来源、章节、PDF页、原始行号、标签、哈希和缺失资产状态；
4. 用SQLite FTS5 trigram建立中文/英文全文索引；
5. 先检索主题卡，再检索原文块，避免把整本书送入模型上下文；
6. 任何公开部署不得向最终用户批量导出受版权保护全文。
