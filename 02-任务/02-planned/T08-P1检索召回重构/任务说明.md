# T08 P1检索召回重构（P1 Retrieval Recall Redesign）

> 状态：PLANNED / NOT STARTED。任务来源：创建者于2026-08-24提交的完整任务计划（原文完整收录于本说明），针对"61个方向大多难以获得超过20篇可用论文、子方向聚类/证据矩阵/研究空白频繁因corpus insufficient终止"的检索召回问题。仓库 `https://github.com/jiangbyxh-sudo/is-im-research-proposal-agent`，基线分支 `p1-retrieval-quality`，工作分支 `p1-adaptive-retrieval-v2`（由基线分支创建）。启动时机由创建者确认；启动后本任务与T06/P4收尾的关系（并行或串行）亦由创建者确认，不改变T06既有门禁。

## 一、任务背景

当前系统有 61 个研究大方向，但大多数方向难以获得超过 20 篇可用论文，导致子方向聚类、证据矩阵和研究空白生成频繁因 corpus insufficient 而终止。

当前主要架构问题是：

1. Direction Profile 同时承载研究方向语义、期刊池和来源准入政策。
2. OpenAlex 的 Precision、Exact Phrase、Topic Recall、Facet Recall 和中文查询多数都带有 approved_source_ids。
3. 当前名为 recall 的 Lane 仍然只在白名单期刊内召回，并不是真正的全库召回。
4. 候选论文进入 Candidate Ledger 后，还会再次按 journal_pool_ids 进行来源资格判断。
5. 不在期刊注册表或不属于方向期刊池的论文通常进入 manual_review，无法进入正式 Evidence Corpus。
6. 当前检索覆盖目标与下游聚类条件不一致：检索阶段约 20/10，聚类完整条件约为 30 篇 direct 和 20 篇有摘要论文。
7. 系统默认要求英文和中文数量，但中文 Provider 和元数据覆盖不足。
8. Semantic Scholar、DBLP 等 Provider 即使启用，也仍可能被来源门禁阻挡。
9. 当前研究空白模块拒绝在证据不足时硬生成，这一原则必须保留。

## 二、硬性架构原则

1. 不得再使用期刊白名单定义研究方向。
2. 研究方向必须由语义字段定义：
   - phenomenon
   - actors
   - contexts
   - mechanisms
   - theories
   - outcomes
   - methods
   - synonyms
   - negative boundaries
3. 期刊白名单保留，但只用于：
   - Precision Seed Lane
   - 来源质量先验
   - 排序加权
   - 证据风险标记
4. 白名单不得成为所有召回 Lane 的硬过滤器。
5. SourceTier.UNKNOWN 不得自动等于 reject 或 manual_review。
6. UNKNOWN 来源只有在完整性、语义或证据不满足时才不能进入 Evidence Corpus。
7. retracted、blacklisted、无效类型、明确无关论文仍必须硬拒绝。
8. 不降低 evidence span 和 gap falsification 的要求。
9. 不允许为了达到数量目标而生成虚假研究空白。
10. 保持现有 API 尽可能向后兼容。
11. 新逻辑必须置于 feature flag 下：
    PROPOSAL_RETRIEVAL_POLICY_V2=1
12. 旧逻辑在 feature flag 关闭时仍可运行。

各 Lane 规则：

Lane B - Global Text
- source_mode=none
- 不允许 approved_source_ids

- source_mode=none
- Topic/Subfield 全库检索
- 不允许 approved_source_ids

Lane D - Facet Expansion
- source_mode=none
- 通过 semantic facets 生成 6–12 条查询
- 同义词 OR，不同 facet AND
- 不得把所有 facet 强制放入同一查询

Lane E - Citation Expansion
- source_mode=none
- 从高分 seed 获取 references、cited-by、related works

Lane F - Historical
- source_mode=none
- 只在 readiness 不满足时扩展到 10 年和 15 年

Lane G - Chinese
- 中文白名单查询只作为 precision 子 Lane
- 同时允许中文关键词的全库查询
- 中文数量不得阻塞整体 readiness，除非用户问题明确要求中国情境

添加单元测试，确保：

- global_text 计划中不存在 primary_location.source.id 过滤；
- global_topic 计划中不存在 approved_source_ids；
- facet 计划中不存在 approved_source_ids；

## 七、实现 AdaptiveRetrievalController

新增 adaptive_retrieval_controller.py。

## 八、重写候选资格

修改 candidate_ledger.py 和 paper_quality.py。

拆分：

- integrity_status
- semantic_status
- evidence_status
- source_quality
- risk_flags
- terminal_status

硬拒绝只包括：

- retracted
- blacklisted source
- invalid document type
- invalid/missing essential metadata
- exact duplicate
- explicit negative-boundary match
- semantic non-relevance
- outside maximum requested window

Evidence Corpus 资格：

integrity_ok
AND semantic_direct
AND evidence_usable

source_tier 不再参与硬资格布尔判断。

对于未注册来源：

- 如果 integrity、semantic 和 evidence 通过：
  terminal_status=eligible
  risk_flags 添加 unregistered_source
- 使用更严格的 semantic/evidence 阈值
- 在排序中获得较低 source_quality 分数
- 不自动 manual_review

保留 manual_review 用于：

- 语义边界模糊
- 出版来源身份冲突
- 摘要和标题明显矛盾
- 可能撤稿但状态无法确认
- 元数据严重不一致

不要将"来源未知"本身作为 manual_review 的充分条件。

## 九、建立三层 Corpus

1. DiscoveryCorpus
- direct
- adjacent
- title-only relevant
- unregistered source
- citation-derived

用于术语发现和引用扩展。

2. EvidenceCorpus
- direct
- integrity pass
- evidence usable

用于聚类、证据矩阵和 gap generation。

3. HighConfidenceCorpus
- EvidenceCorpus 中来源质量较高或经过强化验证的论文

用于核心论断、反证检索和最终引用排序。

API 中分别返回数量，不必默认返回所有完整记录。

## 十六、初始验收门槛

覆盖：

- 61/61 有 readiness 或 saturation reason；
- direct corpus 中位数 >= 30；
- 至少 80% 方向达到 Degraded 以上，或被证明真实饱和；
- evidence coverage 中位数 >= 70%；
- 原不足 20 的方向中，source-free lanes 有可测增量；
- 每个方向均有 lane contribution 和 source-gate audit。

精度：

- 人工抽样 Top 10 precision >= 0.80；
- 与旧版本精度基线相比下降不得超过 3 个百分点；
- 未注册来源单独抽样；
- 撤稿和黑名单论文不得进入 Evidence Corpus。

研究空白：

- Formal Gap 100% 具有 evidence spans；
- Formal Gap 100% 执行 counter-search；
- Exploratory Corpus 不得产生高置信 Formal Gap；
- 不得为了满足数量而硬填 cluster 或 gap。
